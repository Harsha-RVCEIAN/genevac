# GenEvac-Sentinel Trajectory Data Contract & Validation Specification

## 1. Purpose of the Trajectory Data Contract

In **GenEvac-Sentinel**, emergency evacuation modeling combines simulation dynamics (Person A) and AI-driven trajectory forecasting (Person B). To ensure that both subsystems interact reliably without tight coupling or state corruption, this document defines the common trajectory data contract.

The primary objectives are:
1. Establish an immutable, type-safe representation of pedestrian observations.
2. Provide a validated, rolling-window prediction-history cache.
3. Expose clean read-only snapshot interfaces for prediction and evaluation.
4. Strictly prevent AI prediction models from modifying authoritative simulation state, clocks, or pedestrian positions.

---

## 2. Observation Schema

Every discrete spatial observation of a pedestrian is encapsulated in a [`TrajectoryObservation`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L42):

```python
@dataclass(frozen=True)
class TrajectoryObservation:
    agent_id: str
    step_index: int
    timestamp: float
    x: float
    y: float
    category: TrajectoryCategory = TrajectoryCategory.SIMULATED
```

### Field Definitions & Constraints

| Field | Type | Constraints | Description |
|---|---|---|---|
| `agent_id` | `str` | Non-empty, non-whitespace string. Cannot be boolean or numeric. | Persistent unique identifier of the pedestrian. |
| `step_index` | `int` | Strictly integer (`type is int`, `bool` rejected), $\ge 0$. | Discrete simulation step index supplied by the simulation engine. |
| `timestamp` | `float` | Finite float or int (`math.isfinite`), $\ge 0.0$. | Physical elapsed simulation time in seconds. |
| `x` | `float` | Finite numerical value (`math.isfinite`). | Cartesian X coordinate in metres. |
| `y` | `float` | Finite numerical value (`math.isfinite`). | Cartesian Y coordinate in metres. |
| `category` | `TrajectoryCategory` | Member of `TrajectoryCategory` enum. | Classification: `OBSERVED`, `SIMULATED`, or `PREDICTED`. |

All instances are frozen (`frozen=True`) upon creation and cannot be mutated.

---

## 3. Agent ID Conventions

1. Agent identifiers must be strings (e.g., `"ped_001"`, `"agent_east_14"`).
2. The simulation engine assigns and manages pedestrian IDs.
3. Empty strings (`""`), whitespace-only strings (`"   "`), or non-string representations (e.g. integer IDs) are rejected at the contract boundary by [`TrajectoryValidator`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L225).

## 4. Coordinate Origin, Directions, and Units

The simulation and prediction contract strictly follows GenEvac's 2D Cartesian spatial frame:

- **Origin**: Top-left corner `(0.0, 0.0)`.
- **Positive X axis**: Extends to the right (eastward).
- **Positive Y axis**: Extends downward (southward).
- **Spatial Units**: Metres ($m$).
- **Temporal Units**: Seconds ($s$).

```text
(0, 0) ---------------------> +X (metres, right)
  |
  |
  |
  v
 +Y (metres, downward)
```

> [!IMPORTANT]
> External datasets (such as ETH/UCY) or MID research scripts that assume centered or bottom-left origins must be explicitly mapped via dedicated adapters. The internal GenEvac prediction components operate strictly in this top-left, downward-Y frame.

## 5. Simulation Time and Step Conventions

1. **Simulation Engine Authority**: Person A's `SimulationEngine` is the sole authority for:
   - `step_index` ($0, 1, 2, \dots$)
   - `timestamp` ($t = \text{step} \times \Delta t$)
2. **No Independent Timestamp Inference**:
   - The trajectory-history buffer and prediction modules do **not** generate timestamps using wall-clock time (`time.time()`).
   - Timestamps must not be inferred from the number of observations in a buffer.
   - The history buffer preserves the exact `step_index` and `timestamp` supplied by the engine.

## 6. Trajectory Categories

The contract defines three distinct categories via [`TrajectoryCategory`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L10):

```python
class TrajectoryCategory(str, Enum):
    OBSERVED = "observed"
    SIMULATED = "simulated"
    PREDICTED = "predicted"
```

1. **Observed Trajectories (`OBSERVED`)**:
   - Trajectories recorded from real-world pedestrians or benchmarks (e.g., ETH/UCY datasets).
   - Used for model pre-training, domain transfer, and offline benchmarking.
2. **Simulated Trajectories (`SIMULATED`)**:
   - Authoritative trajectory observations generated by GenEvac's `SimulationEngine`.
   - Used as ground-truth for evacuation evaluation and as runtime history for AI prediction.
3. **Predicted Trajectories (`PREDICTED`)**:
   - Forward-looking trajectory forecasts produced by an AI or mathematical prediction model.
   - **Never mixed into the authoritative history buffer.**
   - **Never treated as ground-truth.**

## 7. Trajectory History Buffer Ownership and Behavior

The [`TrajectoryHistoryBuffer`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/__init__.py#L18) serves as the prediction-history cache owned by Person B.

### Operational Principles

1. **Isolation**: Maintains a separate `collections.deque` per `agent_id`.
2. **Chronological Ordering**: Enforces strictly increasing `step_index` and `timestamp`.
3. **Duplicate Rejection**: Rejects duplicate observations for the same agent at the same `step_index`.
4. **Out-of-Order Rejection**: Rejects observations arriving with an earlier `step_index` or non-increasing `timestamp`.
5. **No State Mutation**: Consuming observations from the buffer never updates pedestrian state or advances the simulation clock.

### Recording Observations

Observations can be recorded either as pre-constructed objects or via field arguments:

```python
# Option A: Direct TrajectoryObservation
buf.record(TrajectoryObservation(agent_id="ped_01", step_index=1, timestamp=0.1, x=2.5, y=3.0))

# Option B: Parameterized call
buf.record(agent_id="ped_01", position=(2.5, 3.0), step_index=1, timestamp=0.1)
```

## 8. Configurable History Length

The rolling-window capacity is configurable via `window_size`:

```python
buf = TrajectoryHistoryBuffer(window_size=20, min_history_required=2)
```

- When the number of observations for an agent reaches `window_size`, the oldest observation is dropped upon recording a newer one, preserving the rolling window.
- **Duration vs. Sample Count**:
  - At $\Delta t = 0.1\text{ s}$, $N = 20$ samples span $\Delta T_{elapsed} = (20 - 1) \times 0.1\text{ s} = 1.9\text{ s}$.
  - A full $2.0\text{ s}$ elapsed window requires $N = 21$ samples ($(21 - 1) \times 0.1\text{ s} = 2.0\text{ s}$).
  - `window_size` is fully configurable to support both conventions without code alterations.
- **Insufficient History**: `buf.has_sufficient_history(agent_id, min_required=...)` identifies whether an agent has accumulated sufficient history, without fabricating artificial observations.

## 9. Read-Only Trajectory Snapshot Interface

To pass simulation observations to AI predictors safely, [`TrajectorySnapshot`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L143) provides an immutable view of the simulation state:

```python
@dataclass(frozen=True)
class TrajectorySnapshot:
    current_step: int
    current_timestamp: float
    timestep: float
    trajectories: Mapping[str, Tuple[TrajectoryObservation, ...]]
```

Obtained via:

```python
snapshot = buf.get_snapshot(current_step=10, current_timestamp=1.0, timestep=0.1)
```

- **Cache Protection**: Returns immutable tuples of observations. Mutating a returned snapshot or its collections is prevented by Python and does not affect the internal history cache.
- **Filtering**: Supports optional `agent_ids` parameter to snapshot only active pedestrians.

## 10. Prediction Result Format

Prediction outputs are strictly separated from actual trajectories using [`PredictedPosition`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L173) and [`TrajectoryPrediction`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L201):

```python
@dataclass(frozen=True)
class PredictedPosition:
    timestamp: float
    x: float
    y: float

@dataclass(frozen=True)
class TrajectoryPrediction:
    agent_id: str
    source_step_index: int
    source_timestamp: float
    predictions: Tuple[PredictedPosition, ...]
    category: TrajectoryCategory = TrajectoryCategory.PREDICTED
```

### Safety Rules

1. `source_step_index` and `source_timestamp` document the exact simulation moment when the prediction was generated (enabling anti-staleness verification).
2. Every `PredictedPosition.timestamp` must be strictly later than `source_timestamp` ($t_{pred} > t_{source}$) and strictly increasing.
3. All coordinates and timestamps must be finite numbers.
4. Prediction outputs are read-only and never alter `Pedestrian` objects or `SimulationEngine`.

## 11. Validation Rules and Error Behavior

All validations are centralized in [`TrajectoryValidator`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L225) and raise [`TrajectoryValidationError`](file:///c:/Users/harsh/projects/genevac/src/genevac/prediction/data_contract.py#L17):

| Check | Failure Condition | Error Raised |
|---|---|---|
| **Agent ID** | Empty, whitespace, or non-string | `TrajectoryValidationError("agent_id must be a non-empty string")` |
| **Step Index** | Negative, float, or boolean | `TrajectoryValidationError("step_index must be non-negative integer")` |
| **Timestamp** | Negative, NaN, Inf, or boolean | `TrajectoryValidationError("timestamp must be finite non-negative")` |
| **Coordinates** | NaN, Inf, or non-numeric | `TrajectoryValidationError("coordinate must be finite number")` |
| **Duplicates** | `obs.step_index == prev_step` | `TrajectoryValidationError("Duplicate observation at step ...")` |
| **Out-of-Order** | `obs.step_index < prev_step` | `TrajectoryValidationError("Out-of-order step_index ...")` |
| **Timestamp Inconsistency** | `obs.timestamp <= prev_time` | `TrajectoryValidationError("Inconsistent timestamp ...")` |
| **Simulated Timestep Drift** | $\|\Delta t - \text{expected\_dt}\| > 10^{-4}$ | `TrajectoryValidationError("Timestamp step discrepancy ...")` |
| **Insufficient History** | $\text{len}(obs) < \text{min\_history}$ | `TrajectoryValidationError("Insufficient history ...")` |
| **Prediction Timestamp** | $t_{pred} \le t_{source}$ | `TrajectoryValidationError("Predicted timestamp must be strictly later ...")` |

## 13. System Responsibilities

### Person A (Simulation Domain)
- Sole authority for `SimulationEngine.step()`, `current_step`, and `timestep`.
- Updates authoritative `Pedestrian` positions and states.
- Supplies `TrajectoryObservation` records to Person B's history cache.

### Person B (AI & Evaluation Domain)
- Maintains the `TrajectoryHistoryBuffer` cache.
- Validates observations and sequences via `TrajectoryValidator`.
- Generates `TrajectorySnapshot` for prediction models.
- Emits read-only `TrajectoryPrediction` results.
- Guarantees zero mutation of simulation state, clocks, or pedestrian positions.

## 14. Known Limitations & Future MID Integration Requirements

1. **Coordinate Transformation Policy**:
   - **GenEvac Adaptation (Agent-Centric)**: Native GenEvac prediction models operate in an **agent-centric coordinate frame**. For each target pedestrian, coordinates are normalized relative to their latest authoritative observation $p_0 = (x_0, y_0)$:
     $$p_{\text{local}} = p_{\text{global}} - p_0$$
     Predictions are reconstructed into global coordinates via:
     $$p_{\text{global}} = p_0 + p_{\text{local}}$$
   - **Original MID Reference Preprocessing (Scene-Mean)**: The original Gutianpei/MID implementation used scene-mean centering ($x - \bar{x}, y - \bar{y}$) across all pedestrians in the camera view (`process_data.py:133-145`).
   - **Distinction & Prohibition**: Scene-mean centering is not translation-invariant and depends on total crowd distribution in the scene. GenEvac strictly uses agent-centric centering. Scene-mean centering must NOT be introduced as an additional transformation. The two coordinate systems must never be silently mixed.
   - **External Benchmark Adapters**: When testing against external datasets (e.g. ETH/UCY), an explicit standalone adapter maps from the external coordinate system to the GenEvac contract.
2. **Sampling Stride Adapter**:
   - GenEvac operates at 10 Hz ($\Delta t = 0.1\text{ s}$). MID operates at 2.5 Hz ($\Delta t = 0.4\text{ s}$). A stride-of-4 subsampling adapter must be used when evaluating MID on GenEvac data.
3. **Execution Separation**:
   - As established in Part 1, the official Gutianpei/MID codebase is quarantined under `research/MID/`. Part 2 establishes the data contract independently so future models can be tested cleanly.
