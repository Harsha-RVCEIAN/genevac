# Phase F: Simulation & Prediction System Compatibility Matrix

This matrix evaluates the compatibility between Person A's existing simulation engine (`src/genevac/`) and the requirements of future trajectory-prediction systems (including MID and alternative learned architectures).

| Concern | Assessment / Finding | Classification | Evidence & Notes |
|---|---|---|---|
| **Pedestrian Identity** | String IDs (`ped.id: str`) are maintained consistently across simulation steps. | **Compatible** | [`src/genevac/pedestrians/__init__.py`](file:///c:/Users/harsh/projects/genevac/src/genevac/pedestrians/__init__.py#L16). Predictor can key observations by agent ID. |
| **Position Representation** | Positions are continuous 2D floats `(x, y)`. | **Compatible** | [`src/genevac/pedestrians/__init__.py`](file:///c:/Users/harsh/projects/genevac/src/genevac/pedestrians/__init__.py#L17). Standard Cartesian frame matches models. |
| **Coordinate Units** | Documented as meters in data models; code performs raw float calculations without enforcement. | **Compatible with documented adaptation** | Person A and B must establish an explicit contract verifying that all inputs/outputs are in meters. |
| **Simulation Time** | Discretized via `current_step: int` and constant `timestep: float` ($dt = 0.1$ s). | **Compatible** | [`src/genevac/simulation/__init__.py`](file:///c:/Users/harsh/projects/genevac/src/genevac/simulation/__init__.py#L10). Elapsed seconds = $step \times dt$. |
| **Sampling Interval** | Simulator runs at $dt = 0.1$ s (10 Hz). Research models (MID) assume $dt = 0.4$ s (2.5 Hz). | **Compatible with documented adaptation** | Module B adapter must subsample 10 Hz simulation ticks by a stride of 4, or train a model native to 10 Hz. |
| **History Length** | `TrajectoryHistoryBuffer` retains up to `window_size = 20` steps (2.0s). Research models expect 8 steps at 2.5 Hz (3.2s = 32 simulation steps). | **Compatible with documented adaptation** | History window must be expanded from 20 to $\ge 32$ simulation steps if feeding models expecting 3.2s of history. |
| **History Timestamps** | `TrajectoryHistoryBuffer` currently stores only `(x, y)` tuples without timestamps or step indices. | **Compatible with documented adaptation** | Requires adding step indices/timestamps to history tuples `(step, x, y)` or assuming uniform fixed $dt$. |
| **Missing Observations** | Newly spawned or obstructed pedestrians may have $< T_{obs}$ historical observations. | **Compatible with documented adaptation** | Module B input validator must implement linear back-padding, velocity extrapolation, or fallback to kinematic baseline. |
| **Prediction Horizon** | Research models output 12 steps at 2.5 Hz (4.8s). Simulation requires predictions aligned with simulation steps. | **Compatible with documented adaptation** | Horizon must be specified in seconds or simulation steps, with interpolation if model stride differs. |
| **Output Structure** | Predictions must remain separate from authoritative pedestrian state. | **Compatible** | `LinearTrajectoryPredictor` returns detached tuples. Preserves Person A's ownership. |
| **Ground Truth Collection** | Future ground-truth positions can be harvested from subsequent simulation steps for offline evaluation. | **Compatible** | Simulation logs can be recorded and evaluated post-run against predictions. |
| **Dataset Compatibility** | ETH/UCY datasets run at 2.5 Hz in real-world plaza scenes; simulator models 10 Hz evacuation dynamics. | **Compatible with documented adaptation** | Benchmarks evaluate model architectures, but evacuation inference requires simulation-specific calibration. |
| **Runtime & Latency** | Full 100-step diffusion model takes $> 1000$ ms per agent batch on CPU. A 10 Hz simulation cannot tolerate $> 100$ ms latency per step. | **Incompatible (MID 100-step)**<br>**Compatible with adaptation (DDIM / Lightweight NN)** | 100-step diffusion cannot run online. Fast 2-step DDIM or feed-forward Transformer/GRU is required for interactive simulation. |
| **Dependencies** | Current project uses Python 3.11 and PyTorch 2.4.1. Official MID requires Python 3.7 and PyTorch 1.7.1. | **Incompatible (Unmodified MID)**<br>**Compatible (Native Module B)** | Do not vendor MID. Build Module B using project's declared dependencies (`pyproject.toml`). |
| **Hardware / CUDA** | Host machine has Intel Arc Graphics (CPU-only PyTorch). MID hardcodes CUDA. | **Incompatible (Unmodified MID)**<br>**Compatible (CPU-optimized NN)** | Candidate models must support pure CPU inference (`torch.device('cpu')`). |
| **Licensing** | MID code is MIT; ETH/UCY datasets are non-commercial academic research. | **Compatible for Academic/Research**<br>**Unresolved for Commercial** | Clearly document non-commercial scope in repository README. |
| **Reproducibility** | Simulation seeds and scenario configurations are parameterised. | **Compatible** | `SimulationEngine(seed=...)` and config files ensure repeatable execution. |
